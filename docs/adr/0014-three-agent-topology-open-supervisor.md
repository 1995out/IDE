# ADR-0014: 三 Agent 拓扑与中栏意图编译组件化（形态开放）

- **状态**: ACCEPTED
- **日期**: 2026-10-30
- **决策人**: 项目架构师 / 用户确权裁决（q12～q16）
- **取代**: 澄清并局部取代 [ADR-0007](./0007-dual-agent-daemon-authority.md) 中关于“需求对话 AI 与 Supervisor 允许共用会话”的表述

---

## 背景与问题陈述

在现行架构设计中：
1. **中栏与右栏角色混杂**：ADR-0007 曾允许“右栏需求对话 AI 与中栏 Supervisor 共用底层适配器或在右栏插话”，导致用户的“自由发散脑暴”与系统“契约编译”互相污染。
2. **中栏实现被静态规则锁死**：现行中栏实现（`daemon/supervisor/rules-l0.ts`）依赖 6 条正则硬编码规则与零工具 AST lint 约束，无法真正理解复杂自然语言意图；但若直接强制绑定完整的 Claude Code 独立会话，又会带来启动时延高、进程生命周期笨重以及计账预算复杂（ADR-0004 关联）的问题。
3. **右栏“伪无 prompt”**：右栏声称是无系统提示的成熟 Agent，但代码中存在 `buildProtectionPromptNotice`（暗中拼入保护清单）以及 `BaselineChatAdapter` 写死架构师人设的问题。

用户在北极星目标中明确拍板（`q12`、`q15`）：
- 右栏需求对话 Agent 为成熟引擎（Claude Code 等），无系统提示词注入，只读脑暴；
- 中栏定位为独立“意图编译组件”，旁观对话，只通过画布（Canvas）交互；
- 其实现形态开放，不锁死为特定的某款模型或重型 CLI，核心指标是能够产出确定性、可合法的结构化施工方案（`SchemePatch`）。

---

## 决策内容

### 1. 三 Agent 职责与物理边界彻底解耦

系统明确划分为三类自主实体与一个确定性守护进程（Daemon）：

1. **右栏 · 需求对话 Agent（AI 搭档）**：
   - **定位**：纯粹只读头脑风暴，陪伴用户探索意图。
   - **约束**：不设系统 Prompt，不注入高级架构师人设；物理剥离 `partner_hint` 与暗中拼接的上下文前缀；工具权限严格锁定为文件只读白名单（`Read, Glob, Grep`）。
   - **交互**：不插手方案签署，不直接指挥 Worker，不宣称方案已生效。

2. **中栏 · Supervisor（意图编译组件 + 画布）**：
   - **定位**：静默旁观用户输入，增量将需求与偏好“编译”为结构化方案草案（`SchemeDraftV2` / `SchemePatch`）。
   - **形态开放**：**不强制绑定为完整的 Claude Code 会话**。无论是单次轻量模型调用、专业编译 Chain、还是专用轻量 Agent，只要满足“能稳定生成合法的 `SchemePatch` JSON 并通过 Daemon 验证”即可。
   - **交互单向化**：**只通过中栏画布（Canvas）与用户交互**，严禁在右栏聊天窗口中插入系统提示或插话确认。

3. **施工 Worker**：
   - **定位**：在独立 Worktree 内依据机器指令（签发合同）闭门施工。
   - **约束**：不参与需求讨论，无权修改未授权路径。

4. **Daemon（裁决者，非 Agent）**：
   - 作为唯一确定性权威，负责状态机流转、物理门禁校验、合同签署生效与 Git 终态合并。

### 2. 授权分水岭与双点击机制（conf-5 落地）

- **审阅内容轻量化/后置**：在开工前，画布不强迫非技术用户审阅庞大的文件改动树、代码 Diff 或底层依赖图；这些技术审计细节后置到“试玩验收幕”；
- **两次物理授权点击保留**：
  1. **“确认开工”点击**：用户对方案目标与偏好范围的确权签署，是生成不可逆合同的前提；
  2. **“合入主线”点击**：用户在试玩通过、查阅验证证据（Evidence）满意后的最终放行；
- **安全门禁绝对不动**：`writable_paths` 物理写沙盒、敏感文件不可触碰清单（`never_touch`）在运行时由 Daemon 实时物理拦截，严禁后置。

### 3. 外网摄取与凭据保险库绑定原则（conf-6 落地）

- 为支持“输入网址+账密复刻网站”的北极星场景，允许为 Worker 开放受控只读外网能力（WebFetch / DOM 提取）；
- **前置硬依赖**：外网能力必须与**凭据保险库（Credential Vault）**同步落地。用户提供的账密凭据必须走独立隔离存储，由 Daemon 托管注入，**严禁明文进入 LLM 对话上下文、合同文本与审计日志**。

---

## 影响与后果

### 正面收益
1. **解除中栏重构的工程包袱**：开发团队无需为了中栏硬去维护两个臃肿的 Claude Code 进程，允许使用响应更快、更轻量的意图编译实现，极大加速 Phase 2 垂直切片落地。
2. **彻底还原右栏自由度**：彻底移除消息前面的“保护提示词补丁”和多余预设，还给用户类似网页端 Claude 的流畅脑暴体验。
3. **兼顾 Cursor 及格线与工程师增量**：砍掉用户不关心的技术审阅负担，但守住了物理沙盒拦截与签署责任分水岭。

### 负面影响与风险
1. 意图编译器需要单独设计 JSON Schema 的修复与容错机制（原 TASKS-J.10 范围）。
2. 在凭据保险库（Vault）未交付前，外网复刻场景依然处于受控封冻状态（符合安全第一原则）。
